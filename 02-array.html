1Cos'è un array

Immagina una fila di scatole tutte uguali, attaccate una all'altra su uno scaffale, con un numero scritto sotto: 0, 1, 2, … Ogni scatola contiene un oggetto dello stesso tipo (tutti numeri, oppure tutte parole). Per prendere un oggetto non serve cercarlo: dici il numero della scatola.

Array

Collezione di elementi dello stesso tipo, ciascuno dei quali è accessibile in base alla posizione (l'indice).

Caratteristiche tipiche:

  • è memorizzato in una porzione contigua di memoria (le scatole sono attaccate);
  • si accede agli elementi tramite indice;
  • il tempo di accesso è indipendente dalla posizione del dato.

Limitazione: è una struttura statica: non si possono aggiungere posizioni.

Un array di n = 6 elementi: gli indici vanno da 0 a n − 1 = 5. Qui A[2] = 2 e A[5] = 6.

Nel corso si scrive A[0..n−1] per dire «array A con indici da 0 a n−1». Come hai annotato tu: gli indici partono da 0 e sono interi. Il range si scrive solo quando serve. Per esempio nella ricercaRic del pacco 3 il parametro è solo array A, perché lì il range non conta.

Perché «statica»? Lo scaffale è stato costruito con quel numero di scatole, e subito dopo l'ultima c'è altra roba. Per avere una scatola in più devi costruire uno scaffale nuovo e spostarci tutto.

2Perché l'accesso costa Θ(1)

Ricordi la differenza tra la macchina di Turing e la RAM (pacco 1)? Sul nastro di Turing per arrivare alla cella 1000 devi passare da tutte quelle prima. La RAM invece legge qualunque cella dicendo il suo numero, in tempo costante.

Un array sfrutta proprio questo. Le scatole sono contigue e tutte della stessa grandezza, quindi la posizione di A[i] si calcola con un solo conto:

indirizzo di A[i] = inizio + i · (grandezza di un elemento)

Esempio: l'array inizia all'indirizzo 1000 e ogni elemento occupa 8 byte (un int a 64 bit). Allora A[3] sta a 1000 + 3·8 = 1024, e A[500] sta a 1000 + 500·8 = 5000. Una moltiplicazione e una somma, sia per l'indice 3 sia per il 500. Quindi accedere ad A[i] costa Θ(1), qualunque sia i.

Perché tutti dello stesso tipo?

Se le scatole avessero grandezze diverse, per sapere dove inizia la scatola 500 dovresti sommare le grandezze delle 500 precedenti: non sarebbe più Θ(1). Tipo unico vuol dire grandezza unica, e quindi la formula funziona.

3Le variabili array sono frecce

Questa è la parte che sorprende. Quando scrivi A, la variabile non contiene le scatole: contiene una freccia verso lo scaffale. Il prof lo dice così:

Variabili array

Le variabili array sono riferimenti (puntatori) all'array.

Allora cosa fa B ← A? Copia la freccia, non lo scaffale. Dopo, A e B indicano lo stesso scaffale. Se scrivi qualcosa usando B, lo trovi anche guardando da A, perché sono lo stesso posto con due nomi.

Sulla lavagna: B ← A, poi B[1] ← 0, poi stampa(A[1]). Stampa 0, non 7! Il 7 è stato cancellato «da B», ma la scatola è la stessa.




  Due nomi, una cosa sola
  
Questo fenomeno si chiama aliasing: A e B sono due nomi per lo stesso oggetto. Non è un errore, ma bisogna saperlo. Se vuoi davvero una copia indipendente, devi creare un array nuovo e copiare gli elementi uno per uno, e questo costa Θ(n).






4Passare un array a una procedura



Lo stesso succede quando un array viene passato a una procedura. Il parametro è una variabile nuova, ma riceve la freccia, non una copia delle scatole.



Dalla lavagna


Procedura azzera (array X[0..n−1])
  for i ← 0 to n − 1 do
    X[i] ← 0

Algoritmo …
  ⋮
  azzera(A)        // X riceve la freccia di A
  ⋮                // qui A contiene tutti 0



Durante la chiamata, X e A indicano lo stesso array. La procedura scrive zeri «tramite X», e quando torna l'algoritmo trova A tutto azzerato. È proprio quello che si vuole: gli algoritmi di ordinamento che vedrai più avanti ordinano l'array che gli passi, non una sua copia.

  Perché conta per i costi
  
Grazie al passaggio per riferimento, chiamare una funzione su un array lungo un milione costa quanto chiamarla su un array lungo 3: si copia solo la freccia. Per questo la ricerca binaria ricorsiva usa spazio Θ(log n) e non di più (pacco 3): ogni record di attivazione contiene solo un puntatore ad A.






5E in Go?



Le slide avvertono: nei linguaggi veri alcune cose possono essere diverse. In Go c'è proprio una differenza importante.



    
  
  • Un array Go ([6]int, lunghezza scritta nel tipo) è passato per valore: la funzione riceve una copia di tutte le scatole. Costa Θ(n) in tempo e in spazio, e le modifiche non arrivano all'originale.
    • 
  
  • Uno slice ([]int, senza lunghezza) contiene un riferimento a un array sottostante, quindi si comporta come il passaggio per riferimento del corso: costa Θ(1) e le modifiche agli elementi si vedono fuori.
    • 




func azzeraArray(x [6]int) { for i := range x { x[i] = 0 } }
func azzeraSlice(x []int)  { for i := range x { x[i] = 0 } }

func main() {
    a := [6]int{5, 7, 2, 4, 7, 6}
    azzeraArray(a)
    fmt.Println(a)   // [5 7 2 4 7 6]  ← invariato: ha azzerato una copia

    s := []int{5, 7, 2, 4, 7, 6}
    azzeraSlice(s)
    fmt.Println(s)   // [0 0 0 0 0 0]  ← cambiato: stessa memoria
}



Quindi, quando traduci in Go lo pseudocodice del corso, usa gli slice: si comportano come gli array delle slide.


Un dettaglio per quando userai append: se lo slice è pieno, Go crea un array nuovo più grande e ci copia tutto. Da quel momento lo slice dentro la funzione e quello fuori possono indicare memorie diverse. È il modo in cui Go aggira il limite «struttura statica».




6Riassunto ed esame




  Da ricordare
  
    
    
  • Array: elementi dello stesso tipo, in memoria contigua, accesso tramite indice in Θ(1), struttura statica.
    • 
    
  • Indirizzo di A[i] = inizio + i · grandezza: per questo l'accesso costa Θ(1).
    • 
    
  • Una variabile array è un riferimento: B ← A copia la freccia, non gli elementi.
    • 
    
  • Nel corso i tipi semplici si passano per valore, i tipi strutturati per riferimento, in tempo Θ(1).
    • 
    
  • In Go gli array si passano per valore (copia, Θ(n)), gli slice come riferimento.
    • 
  






  Per l'esame
  
Queste regole servono soprattutto per fare i conti giusti. Quando calcoli tempo e spazio di un algoritmo ricorsivo su un array (ricerca binaria, mergesort, quicksort…), ogni chiamata riceve solo un puntatore: il passaggio costa Θ(1) e il record di attivazione occupa Θ(1) per l'array. All'orale ti possono chiedere perché.






7Esercizi




  1. A ← [1, 2, 3]; B ← A; B[0] ← 9; C ← B; C[2] ← 7. Cosa contiene A?
  

    
A, B e C sono tre frecce verso lo stesso array. Le due modifiche cambiano quell'array: A = [9, 2, 7].

  






  2. Procedura raddoppia(intero k): k ← 2·k. Con a ← 5; raddoppia(a); stampa(a), cosa si stampa?
  

    
5. Un intero è un tipo semplice e si passa per valore: k è una copia di a. Raddoppiare k non tocca a.

  






  3. Un array inizia all'indirizzo 2000 e ogni elemento occupa 4 byte. Dove sta A[10]?
  

    
2000 + 10 · 4 = 2040. Il calcolo è lo stesso per ogni indice, quindi l'accesso costa Θ(1).

  






  4. In Go: func f(a [3]int) { a[0] = 100 }. Dopo v := [3]int{1,2,3}; f(v), quanto vale v[0]? E con []int?
  

    
Con [3]int l'array è copiato, quindi v[0] resta 1. Con []int la funzione modifica la stessa memoria, quindi diventa 100.

  






  5. Se nella ricerca binaria ricorsiva l'array fosse passato per valore (copiato a ogni chiamata), quanto costerebbe?
  

    
Le chiamate sono al massimo 2 + log2 n, e ognuna copierebbe tutto l'array: si passa sempre A intero, sono sx e dx a delimitare la porzione. Ogni chiamata costerebbe Θ(n), quindi il totale sarebbe Θ(n log n), peggio della ricerca sequenziale Θ(n)! Anche lo spazio diventerebbe Θ(n log n), perché ogni record conterrebbe una copia di A.
